02 / CONNECT THE DOTS.

一条命令的另一端，
是你的 Mac。

让已有的自动化，多一个抵达你的方式。
不需要给脚本安装专用 SDK。

  1. 01

    配置订阅与 Note

    打开菜单栏中的设置，选择 ntfy 服务器，可添加多个订阅，并为每个订阅设置可选 Note；需要认证时填入 Token。

  2. 02

    保存连接，允许通知

    保存并连接，在 macOS 提示时允许通知。之后，应用会在菜单栏等候消息。

  3. 03

    从任意脚本发来消息

    用 ntfy 的 HTTP POST 发布，也可以在应用设置内手动发送。应用内发布会发送到第一个已配置的 Topic。

TERMINAL
# 把 <your-random-topic> 换成你的 Topic
$ curl \
    -H "Title: Task complete" \
    -d "All done. Take a break." \
    "https://ntfy.sh/<your-random-topic>"
SCRIPT → NTFY SERVER → YOUR MAC

公开服务器上，无访问控制的 Topic 并不私密。
使用难以猜测的名称，不要发送敏感信息。

03 / KNOW WHERE IT GOES.

连接很简单。
边界也要清楚。

你的消息，经过你选择的 ntfy 服务器。
不是「完全离线」，也不是「消息不出电脑」。

消息与设置

服务器地址、订阅 Topic 和 Note 保存在本机偏好设置；Token 保存在系统钥匙串。面板在内存中保留最近 50 条消息，退出后不作为本地历史持久保存。

传输与展示

服务器会处理消息，存储策略取决于其配置。消息会展示在 macOS 通知中；是否在锁屏显示预览，由你的系统通知设置决定。

这个网站

没有统计脚本、广告或表单。演示只在浏览器里运行，不发真实通知。网站托管服务器可能记录正常访问日志。

04 / A FEW GOOD QUESTIONS.

想知道的，
直接说清楚。

支持哪些 Mac？+

当前 v0.1.0 安装包适用于 Apple silicon（M 系列芯片）的 Mac，需要 macOS 13 或更新版本。目前没有提供 Intel、Windows 或 Linux 安装包。

下载后怎么安装？为什么可能被系统拦截？+

解压 ZIP，将 ntfy-native-0.1.0.app 移入「应用程序」，然后打开。当前版本仅有 ad-hoc 签名，尚未通过 Apple Developer ID 签名与公证，macOS 可能阻止首次打开。请先确认下载来源，再按系统提示在「系统设置 → 隐私与安全性」中批准。不要为了安装关闭系统安全保护。

需要一直运行吗？能同时订阅多个 Topic 吗？+

接收消息需要应用保持运行并连接网络，Mac 睡眠时不承诺实时送达。当前主分支源码支持在同一服务器和 Token 下同时订阅多个 Topic，并为每个订阅设置可选 Note；主面板以 Note 代替 Topic 名称显示。注意：当前 v0.1.0 下载包早于此功能，仍一次订阅一个 Topic；构建主分支源码即可使用多订阅功能。菜单栏面板显示最近 50 条，不是完整的通知归档工具。

登录时启动可用吗？+

设置内提供登录时启动开关，使用 macOS 原生 SMAppService。已验证本机注册、注销和状态持久化，但尚未实测注销或重启 Mac 后的真实登录启动，不把它作为已完成的端到端保证。

这是 ntfy 官方客户端吗？源码公开吗？+

不是。这是独立开发的 macOS 客户端，与 ntfy 官方没有隶属关系。应用源码已在 GitHub 公开，采用 MIT 许可证。当前 v0.1.0 下载包仍是早期单 Topic 版本。

当前版本还有什么已知限制？+

这是早期版本。GitHub 上的 v0.1.0 安装包尚未包含多订阅与 Note；该功能已在公开主分支源码中。部分本机通知场景曾出现系统灰色占位图标，修复情况仍需进一步确认。尚未逐一验证其他 macOS 版本；Liquid Glass 使用 macOS 26+ 原生材质，旧系统使用原生材质回退。

遇到问题怎么反馈？+

优先在 GitHub 提 Issue，写清系统版本和复现步骤；也可以发邮件到 tim@timhuang.net。
